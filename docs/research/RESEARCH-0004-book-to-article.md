# RESEARCH-0004 — Book → Article Reverse Engineering

> Product Discovery（P1 阶段）。只读分析，逆向拆解"一本书如何最终变成一篇优秀读书博文"，作为重新规划 M2（Creative Engine）的事实输入。
> 本文档不提出解决方案、不设计、不写 RFC、不改代码/测试。所有对 ArkMind 现状的描述基于 `main` 当前代码（commit 参考 `a3f946f`）。

---

## 1. 创作流程拆解（只拆，不设计）

把"一本书 → 一篇优秀读书博文"拆成人类作者实际经历的环节：

```
一本书
  │  通读 / 检索
  ▼
值得记录的内容（原始摘录、事实、定义、案例）
  │  判断哪些对读者有价值
  ▼
值得分享的内容（有洞见、反常识、可迁移的点）
  │  归类、找共性
  ▼
可组合的素材（把分散的点按语义聚到一起）
  │  抽象出共同话题
  ▼
主题（Topic：这篇博文到底谈什么）
  │  在主题上形成立场
  ▼
观点（Insight：作者的判断/取舍/对比，常需跨章节甚至跨书）
  │  为观点服务地排序、取舍
  ▼
结构（Outline：开头钩子 → 论证 → 例证 → 结论）
  │  起一个让人想点的名字
  ▼
标题（Title）
  │  按平台语气填充成文
  ▼
文章（适配平台风格的成稿）
```

关键观察（事实，非设计）：
- 前半段（书 → 值得记录 → 值得分享）是**知识组织**问题。
- 后半段（主题 → 观点 → 结构 → 标题 → 成文）是**创作**问题。
- 两段之间的分界点是"**主题（Topic）**"：在此之前是"有什么"，在此之后是"要表达什么"。
- "观点（Insight）"通常**跨 Fragment、跨 Knowledge、甚至跨书**产生，不是单条知识能给出的。

## 2. ArkMind 当前能力与缺口（Gap Analysis）

以当前 Pipeline（`Source → Fragment → Knowledge → Taxonomy → Normalizer → Deduplicator → Provenance`，`KnowledgeReferenceDetector` 已实现未接入）对照第 1 节流程：

| 创作环节 | 对应能力 | ArkMind 现状 |
|---|---|---|
| 一本书（输入） | Source 注册 + PDF 采集 | ✅ `Source` / `PdfSourceProvider` |
| 值得记录 | 切片成可寻址单元 | ✅ `Fragment`（内容寻址） |
| 结构化知识 | 抽取知识条目 | ✅ `Knowledge` |
| 分类 | 知识类型标注 | ✅ `Taxonomy`（`kind`） |
| 清洗 | 归一化 | ✅ `Normalizer`（`normalized`） |
| 去重 | 重复折叠 | ✅ `Deduplicator`（当前数据集未触发） |
| 可追溯 | 来源链 | ✅ `Provenance` |
| 引用关系 | Knowledge→Function | 🟡 `KnowledgeReferenceDetector` 已实现，**未接入 Pipeline**、未持久化 |
| **主题（Topic）** | 把知识聚成主题 | ❌ 无 |
| **主题关系（Topic Graph）** | 主题之间的关联 | ❌ 无 |
| **观点（Insight）** | 跨知识/跨书的判断 | ❌ 无 |
| **结构（Outline）** | 文章骨架 | ❌ 无 |
| **标题（Title）** | 命名 | ❌ 无 |
| **渲染（Renderer）** | 平台风格成文 | ❌ 无 |

一句话概括：**ArkMind 已经把"书 → 结构化知识"这一段做扎实了，但"知识 → 文章"这一整段完全是空白。** 分界点恰好落在第 1 节指出的 Topic 之前。

## 3. 优秀读书博文需要哪些中间能力（输入 → 知识组织 → 输出）

不谈 AI、不谈 Prompt，只从"输入 → 知识组织 → 输出"三段看一篇好博文**结构上**必须具备什么，以及 ArkMind 缺哪一环：

```
输入        已有：Source / Fragment / Knowledge（扎实）
  ▼
知识组织    部分有：分类 / 归一 / 去重 / 引用
            缺：Topic（聚合）、Topic 关系、跨书 Insight
  ▼
输出        全缺：Outline（结构）、Title、平台 Renderer
```

"好"的读书博文相较"知识罗列"多出来的东西（事实层面）：
- **有主题聚焦**：不是把 941 条知识倒出来，而是围绕一个 Topic 取舍。→ 缺 Topic Engine。
- **有观点**：读者记住的是判断/对比/取舍，而非事实本身。→ 缺 Insight（且必须跨条目组织）。
- **有结构**：钩子→论证→例证→结论的可读顺序。→ 缺 Outline。
- **有可信度**：观点能回溯到书中出处。→ 这一点 ArkMind 反而**已具备基础**（Provenance 来源链），是相对同类工具的潜在优势。
- **有平台适配**：同一套内容按平台语气改写。→ 缺 Renderer。

结论（事实）：缺的不是"更强的知识抽取"，而是**从知识到表达之间的三层**——聚合（Topic）、判断（Insight）、成文（Outline/Title/Renderer）。

## 4. 平台分析：共性、差异、共享的 Knowledge

| 平台 | 典型形态 | 语气/风格 | 结构偏好 | 长度 |
|---|---|---|---|---|
| 知乎 | 深度回答/文章 | 理性、论证、可引用 | 论点+论据+延伸 | 中长 |
| 公众号 | 推文 | 有观点、有节奏、可读性强 | 钩子开头+小标题分段 | 中长 |
| 小红书 | 笔记 | 口语、情绪、利他感 | 短段+emoji+要点清单 | 短 |
| 头条 | 资讯/科普 | 通俗、信息密度 | 标题党倾向+快节奏 | 短中 |
| B站稿件 | 视频文案 | 口播、有起承转合 | 脚本化、强开场 | 中长 |

**共同需要的（与平台无关）**：
- 一个明确的**主题**；
- 若干**观点/结论**；
- 支撑观点的**素材（Knowledge + 出处）**；
- 一个**标题**；
- 一条基本的**结构骨架**。

**差异只在最后一层（表达层）**：语气、长度、分段方式、emoji、开场钩子——这些是**渲染风格**，不改变底层知识与观点。

**关键事实**：知乎/公众号/小红书/头条/B站的稿件，**共享同一套 Topic + Insight + Knowledge**，只是 Renderer 不同。这意味着——平台适配应是**最外层、最薄的一层**，中间的 Topic/Insight/Outline 是平台无关的、可复用的核心资产。（此处只陈述事实，不给设计。）

## 最终回答：ArkMind 距离真正生成读书博文，还缺哪些能力？

按"从有知识到出文章"的顺序，缺口是连续的一整段：

1. **Topic（主题聚合）**——把离散 Knowledge 聚成"这篇讲什么"。当前完全没有。
2. **Topic 关系（主题图）**——主题之间的关联，支撑选题与延伸。当前没有。
3. **Insight（观点组织）**——跨 Knowledge、跨书形成判断/对比/取舍。当前没有，且这是"好博文"与"知识罗列"的分水岭。
4. **Outline（结构）**——把观点排成可读的文章骨架。当前没有。
5. **Title（标题）**——命名。当前没有。
6. **Renderer（平台风格输出）**——同一套内容按平台语气成文。当前没有。

补充两点事实：
- ArkMind **已经具备**的"输入 → 结构化知识 + 可追溯 Provenance"是这条链路扎实的地基，尤其 Provenance 让"观点可回溯到书"成为潜在差异化能力。
- 缺的六项中，**前三项（Topic / Topic 关系 / Insight）属于"知识组织的更高层"，后三项（Outline / Title / Renderer）属于"创作/表达层"**；平台差异只落在最后的 Renderer。

以上为事实分析，不含解决方案、不含 RFC、不含设计。
