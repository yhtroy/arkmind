# ADR-0002：不要过早设计（YAGNI）

- 状态：Accepted
- 日期：2026-07-27

## 决策

只为当前 Milestone 的真实需求做设计。任何组件的引入都必须有明确理由，"以后可能用到"不是理由。

## 背景

架构师最容易犯的错误是"设计未来十年"。现在只有一个输入（得到 PDF），就不设计 YouTube、播客、直播、课程、Agent Marketplace。需要的时候再长出来。

## 当前的具体裁决（有人再提，指向本文件）

| 提议 | 裁决 | 理由 |
| --- | --- | --- |
| Neo4j / 知识图谱 | ❌ 拒绝 | 目前没有图查询需求 |
| LangGraph / Dify | ❌ 拒绝 | 现在的 Pipeline 用 Python 100 行写完 |
| Milvus / Qdrant / Pinecone | ❌ 拒绝 | PostgreSQL + pgvector 够了 |
| Kafka / 消息队列 | ❌ 拒绝 | 一本书不需要消息队列 |
| Elasticsearch | ⏸ 暂缓 | PG FTS 先用着，撑不住再说 |
| Celery | ⏸ 暂缓 | 真出现异步需求再引入 |
| Web 前端 | ⏸ 暂缓 | CLI + API 足够 |

## 后果

- 每引入一个新依赖，必须新增一条 ADR 说明理由。
- 架构评审的默认答案是"不要"，提议方负责举证。
- 这个项目的日常工作是**不停删东西**，不是不停加东西。
